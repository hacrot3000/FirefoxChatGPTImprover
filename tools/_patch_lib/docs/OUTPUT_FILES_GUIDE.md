# Patch Tool output files — what each file means

Updated for **Python Patch Tool v5.16.0**.

## Normal rule

In almost every failure case, upload only the file marked:

```text
[PRIMARY - UPLOAD] PTV_<time>_<id>_<STATUS>_HANDOFF.zip
```

By default v5.16 creates only two AI-facing ZIPs: HANDOFF and DETAIL. The older standalone SUMMARY/CODE ZIPs are compatibility-only and are not generated unless explicitly enabled.

## File meanings

| Console label | File pattern | Meaning | When to use |
|---|---|---|---|
| **PRIMARY - UPLOAD** | `PTV_<time>_<id>_<STATUS>_HANDOFF.zip` | Compact all-in-one package containing root causes, important logs, relevant code, patch payload, environment summary and next AI action | **Upload this file first in normal cases** |
| Compatibility only | `PTV_<time>_<id>_<STATUS>_SUMMARY.zip` | Historical split summary bundle | Not generated by default; enable only for older tooling |
| Compatibility only | `PTV_<time>_<id>_<STATUS>_CODE.zip` | Historical split code-context bundle | Not generated by default; enable only for older tooling |
| Debug only | `PTV_<time>_<id>_<STATUS>_DETAIL.zip` | Complete redacted raw logs, runner evidence, Git state and machine-readable diagnostics | Upload only when AI asks for raw/deep evidence |
| Alias | `REPORT ZIP` | Normally another label for the same physical `DETAIL.zip` file | It is not a fifth ZIP |
| Local info | `LAST_RUN.md` | Human-readable status of the latest local run and skipped patches | Read locally; do not upload unless asked |
| Local state | `last_run.json` | Machine-readable latest-run status for scripts/tools | Not normally uploaded |

## Color convention

When the terminal supports ANSI color:

- **Bright green**: primary file to upload.
- **Cyan**: optional split bundle.
- **Yellow**: debug-only/detail evidence.
- **Blue**: local information such as project root and LAST_RUN.
- **Bright green**: PASS / completed.
- **Red**: FAIL or user-deleted queue item.
- **Yellow**: SKIPPED / not executed / warnings.
- **Cyan**: CANCELLED.
- **Blue**: IDLE/local information.

When color is unavailable, the textual labels remain authoritative:

```text
[PRIMARY - UPLOAD]
[OPTIONAL]
[DEBUG ONLY]
[LOCAL INFO]
[ALIAS]
```

## Paths

Console-critical paths are absolute by default. The runner also prints the absolute project root at the beginning and in the final summary. Portable JSON/report metadata continues to use relative paths where appropriate.

Color can be controlled in project configuration:

```json
{
  "console": {
    "color": "auto",
    "critical_paths": "absolute",
    "show_bundle_guide": true,
    "live_status": true,
    "live_status_interval_seconds": 0.5
  }
}
```

Supported color values: `auto`, `always`, `never`. The standard `NO_COLOR` environment variable disables color; `FORCE_COLOR=1` enables it.

## Short bundle filenames

Bundle filenames no longer repeat the often very long original patch filename. The normal format is:

```text
PTV_260807_115400_a1b2c3_FAIL_HANDOFF.zip
PTV_260807_115400_a1b2c3_FAIL_SUMMARY.zip
PTV_260807_115400_a1b2c3_FAIL_CODE.zip
PTV_260807_115400_a1b2c3_FAIL_DETAIL.zip
```

The console and `LAST_RUN.md/json` preserve the mapping back to the actual patch filename that ran.

## Live task status

Long operations show one ephemeral TTY line such as:

```text
⏳ POST COMMAND 1/1: compile_debug_logs.py | 37.2s | process alive | output lines=184
```

The line is rewritten in place, is not appended to the console history, and is deliberately excluded from runner/HANDOFF/DETAIL logs. It covers sandbox overlay, patch payloads, idempotency, post commands, validation, verified-delta apply, Git and AI-bundle creation.

Disable it with `console.live_status=false`.
